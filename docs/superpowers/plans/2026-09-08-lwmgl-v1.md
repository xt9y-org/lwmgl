# lwmgl v1.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `lwmgl v1.0.0`, a standalone macOS Metal wrapper with a plain-C ABI usable identically from C and C++, matching `lwcgl`'s repository/build/install style and providing the GPU facilities required by `xt9y/Horse`'s path tracer.

**Architecture:** `lwmgl` exposes one C-compatible function-table surface named `Metal`, opaque resource handles, fixed-layout descriptors, and thread-local error reporting. Internally, Objective-C++ bridges GLFW's native Cocoa window to `CAMetalLayer` and wraps Metal device, queue, resource, shader, pipeline, command, presentation, synchronization, and acceleration-structure objects. `Horse` integration is intentionally excluded from this plan and gets a separate implementation plan after `lwmgl` passes its own standalone and staged-install verification.

**Tech Stack:** C11 public ABI, C++17 consumer compatibility, Objective-C++17 implementation, Apple Metal, QuartzCore, AppKit, GLFW 3.3+, Make, pkg-config.

**Spec:** `docs/superpowers/specs/2026-09-08-lwmgl-metal-wrapper-design.md`

## Global Constraints

- Repository: `xt9y/lwmgl`.
- Initial library version: `1.0.0`.
- Initial ABI version: `1`.
- Version 1.0.0 supports macOS only; unsupported hosts fail clearly at build time.
- Public headers compile independently as C11 and C++17 or newer.
- Public ABI contains no Objective-C types, C++ classes, templates, exceptions, STL types, or Metal framework declarations.
- The core library does not link against or require any `lwcgl` symbol.
- GLFW may be used to convert the externally owned window pointer to the native Cocoa window, matching the currently tested integration with `lwcgl`.
- `README` has no `.md` extension and states that the project is currently only tested together with `https://github.com/xt9y/lwcgl`.
- Normal install path is exactly `make && sudo make install`.
- `make check`, `make clean`, and `sudo make uninstall` are supported.
- Install paths mirror `lwcgl`: versioned include directory, versioned static/shared libraries, unversioned aliases, and pkg-config metadata.
- Shared library install name is `@rpath/liblwmgl-1.0.0.dylib`.
- `lwmgl` owns only Metal-facing resources; it never creates or destroys the caller-owned application window.
- No renderer, ECS, model loading, scene policy, path-tracing algorithm, GLSL translation, or rasterization fallback is implemented in `lwmgl`.
- No unconditional GPU wait is hidden in normal frame submission.
- No hidden background threads.
- No shader recompilation or resource recreation per frame unless explicitly requested.


Rules:
- only one encoder active at a time;
- switching encoder type ends the previous encoder cleanly;
- `commit` ends any active encoder;
- `wait` is legal only after commit;
- `destroyCommand` never injects a wait;
- invalid order returns error instead of crashing.

- [ ] **Step 4: Implement compute dispatch geometry**

For `dispatch(x,y,z)`, use `dispatchThreads:threadsPerThreadgroup:`. Derive threadgroup dimensions from pipeline `maxTotalThreadsPerThreadgroup` and `threadExecutionWidth`; for a 1D dispatch use width `min(max(threadExecutionWidth,1), maxTotalThreadsPerThreadgroup)` and height/depth 1. For 2D/3D dispatch, choose dimensions whose product does not exceed the pipeline maximum and clamp each dimension to at least 1.

- [ ] **Step 5: Implement explicit idle wait without per-frame hidden stalls**

`Metal.waitIdle()` creates and commits an empty command buffer and waits for completion. It is for teardown/tests/debugging only; ordinary `commit` returns immediately.
